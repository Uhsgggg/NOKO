# 小栗｜球が壁・敵に当たったら跳ね返す

**目標：球が壁に当たると跳ね返り、別の球に当たるとその球も動く。**
担当表：19–24,36行（ID5,9）。ブランチ：`feature/collision`

最初から連鎖やダメージを全部作らない。壁の反射 → 球同士の衝突 → 回数と通知 → 軌道表示（優先度C）の順。

## 1. 作るファイル

場所は `Source/Game/` 以下。配布済みのhに合わせてcppを書く。

| ファイル | 役割 |
|---|---|
| Components/ColliderComponent.h/.cpp | 物体の種類、当たり判定の形や大きさを覚える |
| Components/ReflectionCounterComponent.h/.cpp | 何回反射したかを覚える |
| Systems/CollisionSystem.h/.cpp | 全物体を調べて衝突・反射させる |

`GameTypes.h` は共通の型が入っている。必要に応じて自分のクラスにprivateの補助関数を作ってよいが、公開関数や共通型は変えない。

## 2. ColliderComponent（当たり判定の設定）

`Configure(const ColliderConfig& config)` で以下の設定を保存し、`GetConfig()` で返す。

| 設定 | 何を表す？ |
|---|---|
| role | Player / Enemy / Boss / Wall のどれか |
| shape | Sphere（球）かBox（箱） |
| radius | 球の半径。正の値 |
| halfExtent.x, halfExtent.z | 箱の中心から端までの距離。正の値 |
| mask | どの種類の相手と当たるか。初期値0xFは4種類すべて |
| restitution | どのくらい跳ね返るか。0〜1 |

設定値が正常な数値か確認する。存在しないrole/shapeや不正なmask、範囲外の半径・係数を受け入れない。

今回は上から見た円と長方形の判定。描画のScaleや回転角度は自動で使わない。例：中心(3,0)、横幅2、奥行き4の箱ならhalfExtent=(1,2)。床にColliderは付けない。ボスや壁は固定物。

**maskの確認方法**：Player=0、Enemy=1、Boss=2、Wall=3番目のビットを割り当てている。`(config.mask & (1u << static_cast<unsigned>(相手のrole))) != 0` なら相手種別を許可している。AからB、BからAの両方で確認する。まず初期値0xFの全種類衝突から作るとよい。

## 3. CollisionSystem::Detect（当たっているか調べる）

`static bool Detect(GameObject& a, GameObject& b, Contact& out)` は、**調べるだけ**の関数。ここで物体を動かさない。

最初に、a/bが有効か、Colliderがあるか、Colliderが有効か、双方のmaskが許可しているか調べる。どれかがNGならfalse。

当たっている場合だけoutに次の情報を入れ、trueを返す。

| Contactの変数 | 入れる値 |
|---|---|
| a / b | 調べた物体へのポインタ（&a / &b） |
| normal | BからAへ押し出す向き。長さ1 |
| penetration | どのくらい重なっているか。0以上 |

### 3-1. 球と球が当たるか

例えば半径0.5の球が2個ある。中心間の距離が2なら当たらず、0.8なら0.2重なる。

1. Aの中心からBの中心を引く。差を(dx,dz)とする。
2. 距離 `d = sqrt(dx*dx + dz*dz)` を求める。
3. `d > 半径A + 半径B` ならfalse。
4. 法線を `(dx/d, dz/d)`、重なりを `半径A + 半径B - d` にする。
5. 中心が完全に一致するとd=0になるので割り算しない。毎回同じ向き（例：+X）を使用する。outを埋めてtrue。

### 3-2. 球と箱が当たるか（まずAが球、Bが箱の場合）

1. 箱のX範囲を `[中心X-半幅X, 中心X+半幅X]` とする。Zも同様。
2. 球の中心Xをその範囲内に収める。Zも同様。これで箱の中・表面にある球中心に一番近い点が得られる。
3. 球中心からその点を引き、距離を計算する。距離が半径より大きければfalse。
4. 距離が0より大きい場合は、その差を距離で割って法線にする。重なりは半径−距離。
5. 球中心が箱の内側または面上だと距離が0になる。箱の左・右・手前・奥のうち、最も近い面を選ぶ。その面の外向きの法線を使い、「半径＋中心からその面までの距離」を重なりにする。同距離なら常に同じ選び方をする。

例：箱の中心(0,0)、半幅(1,1)、球中心(1.4,0)、半径0.5。箱の最寄り点は(1,0)。法線(+1,0)、重なり0.1。

Aが箱、Bが球の順なら、球と箱として計算し、最後にa/bを元の順に戻して法線のX/Zの符号を反転する。箱同士は今回は対象外。

## 4. CollisionSystem::Reflect（固定壁で跳ね返る速度を計算）

`static BoardVec2 Reflect(BoardVec2 velocity, BoardVec2 normal, float restitution)` を作る。位置は変えず、跳ね返った後の速度だけを返す。

```cpp
float dot = velocity.x * normal.x + velocity.z * normal.z;
if (dot >= 0.0f) return velocity; // 壁から離れる方向ならそのまま
float k = (1.0f + restitution) * dot;
return {velocity.x - k * normal.x,
        velocity.z - k * normal.z};
```

normalは長さ1の前提。両者で反発係数が異なる場合は小さい方を使う（仮ルール）。例：速度(-2,1)、壁から球へ向く法線(+1,0)、反発係数1 → 速度(+2,1)。壁に沿う方向の速度は変えない。

## 5. CollisionSystem::Step（全物体を調べて実際に動かす）

SceneGameから `Step(objects, outNotices)` が呼ばれる。配列の0番と1番、0番と2番、1番と2番……のように全組を1回ずつ調べる。二重に調べない。

```cpp
for (size_t i = 0; i < objects.size(); ++i)
{
    for (size_t j = i + 1; j < objects.size(); ++j)
    {
        // 空のポインタを除外
        // Detectで当たっているか確認
        // 当たっていたら位置補正・速度変更・通知
    }
}
```

毎回最新の位置を使ってDetectする。Player/EnemyはBallMotionがあって有効なときだけ動球として処理する。設定が欠けている場合はリードへ報告。Wall/Bossは固定。実際に移動していない球も、衝突で動くようにする。

### 5-1. 球と固定物

- めり込みがあれば球だけ外に出す。球がAの場合、X/Zに `normal × penetration` を足す。球がBの場合は逆向きに足す。
- 球が固定物に近づく方向なら、Reflectで速度を計算してBallMotion::SetVelocityに渡す。球がBの場合には法線を反転する。
- 固定物の位置・速度は変えない。離れようとしている球は再度反射させない。

### 5-2. 球と球

両方の球を重なりの半分ずつ逆方向に押し出す。Aには `normal × penetration / 2`、Bにはその逆向きの値を足す。

反射前の速度をvA/vBとし、`s = (vA.x-vB.x)*normal.x + (vA.z-vB.z)*normal.z` とする。sが0以上なら、互いに離れているので速度変更なし。

sが負なら、両球の重さが同じとして `k = -(1+e)*s/2` を計算する。Aの速度には `k*normal` を足し、Bからは引く。eは反発係数（小さい方）。両方の新しい速度を計算してからSetVelocityする。

例：Aが(2,0)で右に進み、Bが止まっていて正面衝突。反発係数1ならAが止まり、Bが(2,0)で進む（最高速度の制限内）。

## 6. ReflectionCounterComponent（反射回数）

| 関数 | 中に書く処理 |
|---|---|
| Reset() | m_count=0 |
| Increment() | m_countを1増やす。INT_MAXを超えないようにする |
| GetCount() | m_countを返す |

Stepの中で、**固定物に近づいて実際に跳ね返った場合だけ** Incrementする（仮仕様）。触れているだけでは増やさない。発射前のResetはリードが行う。Cloneでは0に戻す。設定のJSON保存は不要。

## 7. 衝突したことをリードへ知らせる

ダメージを計算するのは遠藤さん、実際にHPを減らすのはリードの接続処理。小栗さんは `CollisionNotice` に情報を詰めるだけ。

- Stepの最初で `outNotices.clear()` する。
- 解決する前の速度・物体の種類を見て攻撃した側を判断する。接近していて前のStepには接触していなかった場合だけ通知する。
- 仮仕様：PlayerがEnemy/Bossに接近して衝突、または動いているEnemyがBossに衝突した場合。Enemy同士のダメージはなし。
- `attacker` に攻撃側、`target` に相手、`reflectionCount` に反射処理後の攻撃側の回数を入れ、outNoticesへ追加する。
- 同じ衝突中に何回もHPが減らないように、`m_previousContacts` に前回接触していたA/Bの組を覚える。i<jの順で保存・比較する。今回の接触組を別の一覧に集めて最後に入れ替える。一度離れて再び衝突したら通知できる。`Reset()` で履歴を空にする。

箱の押し出しによるごく小さな再接触や、速すぎて壁をすり抜ける場合はリードと相談する。細かな補正や再計算はまず基本判定を作った後に検討する。

## 8. 使える関数・提出物

`GetTransform()`, `GetComponent<ColliderComponent>()`, `GetComponent<BallMotionComponent>()`, `GetComponent<ReflectionCounterComponent>()`, `IsEnabled()`, `IsActive()`（リードが追加予定）。栗本さんの `GetVelocity()/SetVelocity()/IsMoving()/Stop()` を使う。取得ポインタがnullptrの場合は処理しない。

ColliderのClone・JSONにはrole/shape/radius/halfExtent/mask/restitutionを引き継ぐ。ReflectionCounterは回数0から始める。Enabledは両方で引き継ぐ。設定入力の検査とInspector、登録コードは共通資料00に従う。

確定した反射点・方向は、必要になったら物理を変えず別のデバッグ用記録に出す（軌道表示、優先度C）。

**禁止：** SceneGame、Registry、Serializer、HP、入力、描画基盤を直接変更しない。衝突ループ中の物体追加・削除、HP減少、撃破、UI描画はしない。

## 9. 完成チェック（順番にテストする）

| テスト | 正解 |
|---|---|
| 半径0.5の2球、距離2 / 0.8 | false / true、重なり0.2 |
| 2球の中心が完全一致 | 0除算やNaNなし |
| 箱半幅(1,1)、球(1.4,0)、半径0.5 | 法線(+1,0)、重なり0.1 |
| 球が箱内部/角、A/B逆順、無効設定、mask除外 | 正しく外向き、法線の反転、無効な物体は判定しない |
| 速度(-2,1)、法線(+1,0)、e=1 | (+2,1)、離れる球なら速度不変 |
| 固定壁とボス | 衝突しても移動しない |
| 正面で2球が衝突（速度2と0、e=1） | 速度が交換され、連鎖できる |
| 触れ続ける／離れて再衝突 | 通知は最初の1回／もう一度可能 |
| Reset、壁で反射、離れる接触 | 回数0→1→1 |
| Play再開始 | 接触履歴が空になる |

## 補足用語

| 用語 | 意味 |
|---|---|
| Collider | 目には見えない、当たり判定用の形 |
| AABB | X/Z軸に平行な箱。今回は回転しない判定を使う |
| 法線 / normal | 壁や相手の体から、自分を外に押し出す方向（長さ1） |
| penetration | 2物体が重なっている深さ |
| 内積 / dot | 2つの向きが同じか逆かを調べる計算。今回の負の値は相手に近づくことを示す |
| 反発係数 / e | 1ならよく跳ね返り、0なら法線方向の跳ね返りがない |
| mask / bit | 当たってよい相手の種類を、小さな整数の各桁で記憶する方法 |
| 接触履歴 | 前回どの組が当たっていたかの一覧。重複通知を防ぐ |
| Step | 物理処理1回分。1フレームに複数回呼ばれることがある |
| 等質量 | 2つの球の重さを同じと考えること |
