## 3. GameObject全体を無効にできるようにする

ファイル：`Source/Engine/Scene/GameObject.h/.cpp`

Componentには既に有効・無効があるが、物体全体をゲームから除外するために次を追加する（現masterに既に追加済みなら重複させない）。

```cpp
// GameObject.h のprivate:
bool m_active = true;

// public:
void SetActive(bool active) { m_active = active; }
bool IsActive() const { return m_active; }
```

1. GameObject::Updateの先頭で `if (!IsActive()) return;` とする。
2. SceneGame::Drawの物体描画ループで無効な物体は描画しない。
3. 小栗さんに衝突判定から除外するよう伝える。生存数・移動中の球・HUD用の敵一覧からも外す。
4. HP0の物体はこの機能で無効にする。すぐにdelete/eraseしない。
5. Play開始時のCloneはactive=trueから始める。JSONには保存しない。編集時のデータはF1で元に戻ることを確認する。

## 4. 画面のマウス座標をゲーム内に変換する

新設案：`BoardPointer.h/.cpp`（場所はGame側で整理）。`BuildPointerFrame(Camera&, const GameObject& player, HWND, float boardY)` などを内部で用意し、栗本さんへ `PointerFrame` を渡す。

### なぜ必要？

マウスは画面の左上から何ピクセルかという値。球の位置は3D空間のX/Y/Z。直接引き算すると正しい発射方向にならない。そこでマウスの位置からゲーム内の地面（球を動かす高さ）を見たときに、どこを指しているか計算する。

### 実装手順

1. `GetCursorPos` でマウス位置を取得し、`ScreenToClient` でゲームウィンドウ内の座標にする。失敗・画面外・フォーカス喪失なら `PointerFrame.valid=false` を返す。
2. `GetRenderWidth()/GetRenderHeight()` とカメラの `GetViewMatrix(false)/GetProjectionMatrix(false)` を取得する。ウィンドウ内座標と描画範囲のサイズが違うなら変換する。幅/高さ0は無効。
3. DirectXMathの `XMVector3Unproject` を使い、同じ画面X/Yで深さ0（near）と1（far）のゲーム空間位置を求める。world行列は単位行列。行列は転置前のものを渡す。
4. `far.y - near.y` が0に近い場合は、地面に向かう線ではないので無効とする。
5. 地面との交差位置を計算する。

```text
 t = (boardY - near.y) / (far.y - near.y)
 point = near + t * (far - near)
```

6. tが負の場合、カメラの後ろに向かうので無効。値が不正でないことを確認し、pointのX/Zを `PointerFrame.point` に入れる。
7. クリックした位置とプレイヤー中心のX/Z距離がColliderの半径内かを確認し、押した瞬間の `hitPlayer` を設定する。
8. Engine/Inputの `IsKeyTrigger/Press/Release(VK_LBUTTON)` がマウスでも動くか実機で確認。動かなければWinAPIの左ボタン状態を前回と比較してpressed/held/releasedを作る。フォーカス喪失時は入力を破棄する。ImGuiやSceneRayPicker（Debug専用）には依存しない。

完成条件：カメラが斜めでも、画面中央/端のクリックが正しいゲーム内位置になる。右方向に引くと左へ飛ぶ。フォーカスを失った場合に勝手に発射しない。

## 5. ComponentRegistryへ登録する

対象：`Source/Game/Components/ComponentRegistry.cpp`。

各担当者の完成したComponentだけを追加。既存Moveを参考に、担当者から提出された3つの処理を登録する。

| 処理 | 何を書く？ |
|---|---|
| create | 受け取った所有者pOwner用のComponentを作って返す |
| save | Getterで設定値を取得しJSONに書く |

## 6. SceneGameへ各機能をつなぐ

ファイル：`Source/Game/Scenes/SceneGame.h/.cpp`（実際の配置は現masterに合わせる）。System追加の書き方そのものは06参照。

`SceneGame.h` のprivateに、完成したSystemを通常のメンバ変数として置く。

```cpp
TurnSystem m_turn;
CollisionSystem m_collision;
```

必要なhをincludeする。DamageFormulaとHudPresenterはstatic関数を使うためメンバ変数は不要。

### 6-1. Play開始・終了と初期化

既存EnterPlayModeで複製に成功し、m_objectsを入れ替えた後に `m_turn.Reset(初期手数)`、`m_collision.Reset()` を行う。ボス撃破やゲーム終了フラグ等も初期化。Exit、Load成功後、Release起動、リスタートでも必要な初期化を行う。古い物体のポインタや接触記録を残さない。Clone/Load失敗時は旧シーンを維持する。

### 6-2. 1フレームの処理順

既存 `SceneGame::Update()` の `if (shouldUpdateGame)` の中につなぐ。Edit中はゲーム更新を動かさない。ゲーム終了後は入力と更新を停止し描画は続ける。

| 順 | 処理の中身 |
|---|---|
| 1 | PlayerのInput、Launch、Motionを取得（なければ発射しない）。PointerFrameを作り、`Sample(frame, m_turn.CanLaunch())` を1回呼ぶ |
| 2 | `GetAim()` の結果から `TryBuildVelocity(aim, velocity)`。成功かつMotionが有効なら `TryConsumeShot()`。成功時だけ全ReflectionCounterをResetし、PlayerのSetVelocityを呼ぶ |
| 3 | `IsResolving()` がtrueの間、1回のdtを4つに分ける。各回、全active物体のUpdate → `m_collision.Step(m_objects, notices)` → ダメージ反映 |
| 4 | 全active・enabled BallMotionの `IsMoving()` を調べ、1つでも動けばanyMoving=trueにする |
| 5 | `m_turn.EndIfStopped(anyMoving)` がtrueの場合だけ勝敗を判定。続行の場合に敵を追加 |
| 6 | HUDに渡す情報を集め `HudPresenter::Build()` を呼ぶ。Drawで描画 |

元の全物体Updateループは物理更新ループと重複させない。手数消費・入力は4分割のループに入れない。待機中もAutoRotate等を動かしたい場合、表示用の更新を別にする。4分割は仮値で高速移動の完全なすり抜け防止ではない。

## 7. ダメージをつなぐ・敵を撃破する

実装先案：`DamageSystem.h/.cpp` またはSceneGameのprivate関数 `ApplyCollisionNotices`。

1. CollisionSystem::Stepの直後に受け取った `CollisionNotice` の一覧を1回ずつ使う。次回へ持ち越さない。
2. attacker/targetのnullptr、有効状態、Colliderのroleを確認。仮仕様に該当する攻撃か再確認する。
3. targetから `GetComponent<HealthComponent>()`。存在し有効なら、`DamageFormula::Calculate(基本値, 倍率, notice.reflectionCount)` を呼び、結果をApplyDamageへ渡す。値は企画で確定する。
4. `IsDead()` がtrueなら `SetActive(false)`。BallMotionがあるならStop。ボスの場合はボス撃破フラグを立てる。同じ敵を二重に撃破として数えない。
5. この時点でvectorから削除しない。ボスも保持し、全動球が止まってから勝敗を判定する。

## 8. 敵を追加・ゲームを終了する

実行時の物体は既存GameObjectFactoryでPrimitiveまたはFbxを作り、TransformやComponentを設定してからm_objectsへ追加する。失敗した場合は追加せず、既存の状態は変更しない。

最初はStage01のPlayer/Enemy/Wall/KingSlime等にInspectorで必要なComponentを付けてもよい。名前は初期設定時の目印に限り、実際のルールはColliderのroleで判定する。物体ごとの構成は共通資料00の表を参照。床はColliderなし、壁は実際のX/Z方向の半幅を手動設定。生成は物理の走査が完了した後に行う。

ゲーム終了は最終手の発射直後ではなく、全動球停止時に決める。ボス撃破と手数切れが重なった場合は仮にクリア優先。雑魚全滅条件・ウェーブの追加数は企画と確定するまで仮と明記する。

## 9. HUDのための描画関数を用意する

黒野さんは `HudInput` を受け取って `HudView` を作る。リード側で次を準備する。

| 必要な機能 | 内容 |
|---|---|
| 数値表示 | 数字PNGを使うなどしてHudView.shotsText/nextEnemiesTextを描画 |
| 矩形・画像 | ボスHPバー全体と、割合に合わせた塗り部分を描画 |
| 敵の色 | 当該フレームの敵順と一致するenemyColorsをSetColorで反映 |
| 矢印 | showArrowのとき、arrowStartからarrowEndへのゲーム内の線を描画 |

既存Spriteの `SetSize/SetColor/SetTexture/SetWorld/SetView/SetProjection/Draw` を調べて使いやすい関数にまとめる。Spriteだけで文字列が描けるわけではない。矢印はGeometory::AddLine/DrawLinesをPlay側でも呼べるようにし、描画後に変更したRenderStateを元に戻す。ImGuiは開発用で、ReleaseのUIには使わない。実際の描画関数名は黒野さんと共有する。

Arnoldのシェーダー完全互換は範囲外。必要ならMayaでテクスチャに焼き込んでFBXに使う等の方法を検討する。

## 補足用語

| 用語 | 意味 |
|---|---|
| 座標変換 / Unproject | 画面の点をゲーム空間上の点へ戻す計算 |
| near / far | カメラから見える範囲の手前と奥の点 |
| ray | マウス位置からゲーム空間へ伸ばす仮想の線 |
| アダプタ | 難しい内部処理を、他担当が使いやすい関数にまとめたもの |
| RenderState | 描画方法の設定（深度、ブレンドなど） |
| ウェーブ | 一定条件で追加される敵の集団 |
| static | オブジェクトを作らなくてもクラス名から呼べる関数など |
| Clone / Reset | コピーの作成 / 状態の初期化 |
| 統合テスト | 各自の機能を組み合わせ、ゲーム全体として確認すること |
