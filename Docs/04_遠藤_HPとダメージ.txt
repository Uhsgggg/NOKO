# 遠藤｜敵のHPとダメージを計算する

**目標：HP10の敵に7ダメージを与えたらHP3。さらに99ダメージを与えてもHP0で止まるようにする。**
担当表：25–26,40–41行（ID6,10）。ブランチ：`feature/health-damage`

当たり判定がまだ完成していなくても、自分の機能だけで作業を進められる。最初は画面に敵が出なくてもよい。

## 1. 作るファイル

配布したhには必要な変数・関数が書いてある。対応するcppに中身を書く。

| 順番 | ファイル（Source/Game/ 以下） | 何をする？ |
|---|---|---|
| 1 | Components/HealthComponent.h/.cpp | HPを持ち、増減させる |
| 2 | Systems/DamageFormula.h/.cpp | 何ダメージになるか計算する |

## 2. HealthComponentを作る（まずHPだけ）

hファイルの `m_hp` が今のHP、`m_maxHP` が最大HP。最初は両方10。

### 作業1：コンストラクタと初期化

例：コンストラクタでは次のように書く。

```cpp
#include "HealthComponent.h"

HealthComponent::HealthComponent(GameObject* pOwner)
    : Component(pOwner)
{
}
```

`Reset(int maxHP)` は最大HPを設定し、現在HPもその値に戻す。maxHPが1未満なら受け入れない。拒否の方法（例：エラーとして呼び出し元に伝える）はリードと統一する。途中まで値を変更しない。

例：Reset(20) → m_maxHP=20、m_hp=20。

### 作業2：HPを取得する3つの関数

| 関数 | 返すもの |
|---|---|
| `GetHP() const` | m_hp |
| `GetMaxHP() const` | m_maxHP |
| `IsDead() const` | m_hpが0ならtrue、それ以外false |

例：`int HealthComponent::GetHP() const { return m_hp; }`

### 作業3：ダメージを受ける関数

```cpp
int HealthComponent::ApplyDamage(int amount)
{
    // 0以下のダメージや、倒れた敵には何もしない
    if (amount <= 0 || m_hp <= 0)
    {
        return 0;
    }

    // 残っているHPより大きくは減らさない
    int actualDamage = amount;
    if (actualDamage > m_hp)
    {
        actualDamage = m_hp;
    }

    m_hp -= actualDamage;
    return actualDamage;
}
```

戻り値は攻撃力ではなく「実際に減ったHP」。例えばHP3の時に99ダメージを受けたら、戻り値は3。

自分では敵を消さない・色を変えない。HPが0か調べる `IsDead()` を使い、リードが敵を画面から消す処理を作る。毎フレームHPを減らす必要もない（Updateの上書き不要）。

### 作業4：複製できるようにする

F1でPlayに切り替えたときにも使う関数。

```cpp
std::unique_ptr<Component> HealthComponent::Clone(
    GameObject* pNewOwner) const
{
    auto pCopy = std::make_unique<HealthComponent>(pNewOwner);
    pCopy->Reset(m_maxHP);
    pCopy->SetEnabled(IsEnabled());
    return pCopy;
}
```

HPが3まで減っていたとしても、最大HP10の新しいComponentを作る。有効/無効の設定だけは元と同じにする。hのGetTypeIdの文字列 `"Health"` は変更しない。引数名はhとcppで違っても動作する。

### 作業5：Inspectorと保存

Inspectorは最大HPを入力できるようにする（不正値を防いでReset）。現在HPは表示するだけ。`DrawDebugInspector()` は `#ifdef _DEBUG` で囲む。既存MoveComponentのInspectorを参考にする。

保存するのは最大HP（maxHP）だけ。現在HPは保存しない。リードに「作る時はHealthComponent(pOwner)、保存はGetMaxHP、読み込みはReset」を伝え、create/save/loadの登録コードを別テキストで提出する。Registry本体は変更しない。

## 3. DamageFormulaを作る（HPとは別のクラス）

Componentではないので、GameObjectに取り付けない。`static int Calculate(float baseDamage, float multiplier, int reflectionCount)` の中身を作るだけ。

| 引数 | 意味 |
|---|---|
| baseDamage | 反射しなくても与える基本ダメージ |
| multiplier | 反射1回ごとにどれくらい増えるか |
| reflectionCount | 反射回数 |

前回からの仮計算式（企画の確定値が出たら変更）：

`ダメージ = 基本ダメージ × (1 + 倍率 × 反射回数)` の小数点以下を切り捨てる。

例：3 × (1 + 0.5 × 2) = 6ダメージ。反射0回なら3ダメージ。

**実装の順番**

1. 基本ダメージと倍率が負の値、または `std::isfinite()` でfalseなら0を返す。
2. 反射回数が負なら0として計算する。
3. double型で上の式を計算する（floatの値をdoubleに変えてから計算）。
4. 結果がintの最大値（`INT_MAX`、`<climits>`）より大きい場合はINT_MAXを返す。
5. `std::floor` または正の値のint変換で小数点以下を切り捨て、intで返す。

CalculateはHPを変更しない。リードがこの関数で計算し、HealthComponentのApplyDamageに渡す。野末・林が決めた正式なダメージ仕様をリードと確認してから式を変える。基本値や倍率を関数の中で固定しない。

自分のテスト用コードや、リードが用意したテスト環境で上から試す。本番Main.cppは勝手に変更しない。

## 5. 使ってよい関数・変更しないファイル

今回使う既存のComponentの機能：`GetOwner()`, `IsEnabled()`, `SetEnabled()`, `Clone()`。GameObjectの内部や他のComponentは基本的に調べなくてよい。

変更しない：GameObject、SceneGame、CollisionSystem、ComponentRegistry、DebugEditor、SceneSerializer、描画関係。敵をdeleteしない。ダメージ通知や撃破の処理はリードが担当。

## 補足用語

| 用語 | 意味 |
|---|---|
| HP | 体力。今回0になったら倒された状態 |
| Getter | 変数の値を返すだけの関数（GetHPなど） |
| Clone | コピーを作る関数。元のHPをそのままコピーする必要はない |
| static関数 | オブジェクトを作らず `DamageFormula::Calculate(...)` と呼べる関数 |
| int / float / double | 整数 / 小数 / より広い精度と範囲で小数を扱う型 |
| floor | 小数点以下を切り捨てる関数（今回の計算結果は0以上） |
| INT_MAX | intで扱える最大値。超えて変換すると正常に動かない可能性がある |
| 単体テスト | ほかの処理とつなぐ前に自分の関数だけ確認すること |
