最初に全員が読む資料／プロトタイプ用（未実装）

1. まず何をする？

1. GitHubから最新の master をプルする。ComponentファイルやSystemsファイルに共通のhファイルが配布されたことを確認する。
2. 自分専用のブランチを作る。以降の作業はそのブランチで行う。
3. 自分の名前が書かれた資料を開く。最初からすべてのクラスを理解しなくてよい。
4. API案/Source の自分の担当クラスのhファイルを見る。hには関数名、受け取る値、返す値が書いてある。cppに関数の中身を書く。
5. 自分の機能だけでテストする。完成した機能からリードに確認してもらい、Pull Requestを出す。

■注意：配布したhファイルは完成品ではない。cppがまだない関数を呼ぶとリンクエラーになる。
　　　　別担当の完成を待つ必要はないが、未完成の機能を本番SceneGameにつないだまま提出しない。
　　　　共通のテスト方法はリード(波多野)に相談する。

3. ゲームの仕組み（現在の設計案）

青い球を引っ張って離す → 球が動く → 壁や敵に当たる → 敵も動く → 全部の球が止まる → 次の発射ができる。

位置は3DのX・Y・Zで管理するが、球の移動・当たり判定にはXとZだけを使う。
Y（高さ）は変えない。BoardVec2 はこの2つの値をまとめた型。画面上のマウス座標とは別のもの。

| 物体 | 付ける機能 |
＝＝＝＝＝＝＝＝＝＝
| プレイヤー | PlayerInput, PlayerLaunch, BallMotion, Collider（Player）, ReflectionCounter |
| 雑魚敵     | BallMotion, Collider（Enemy）, ReflectionCounter, Health |
| ボス       | Collider（Boss）, Health。動かさない |
| 壁・箱     | Collider（Wall）。動かさない |
| 床         | Colliderなし（今回はXZ平面だけで判定する） |
＝＝＝＝＝＝＝＝＝＝

見た目の大きさと、当たったと判断する大きさは別に設定する。
箱の判定はX/Z軸に平行な長方形だけに対応する。
回転して見える外周壁も、実際に盤面に占めるX/Z方向の半分の幅を手で設定する。
自由な角度の箱への対応は後回し。

事前に用意してある MoveComponent と新しい BallMotionComponent は同時に付けない。
両方が位置を変えると2回移動してしまう。見た目の回転用AutoRotateは使用可能。

4. 1回の更新で何をする？（リードが順番を管理）

| 順番 | 内容 | 担当 |
＝＝＝＝＝＝＝＝＝＝
| 1 | Play中でゲーム終了前か確認 | 波多野 |
| 2 | マウスの位置・押した/離した情報を渡す | 波多野 → 栗本 |
| 3 | 発射できる場合、速度を計算し手数を1減らす。全動球の反射回数を0にしてから発射 | 栗本・波多野 |
| 4 | 球を少し動かす → 衝突を調べて跳ね返す → ダメージを反映 → HP0を無効にする | 栗本 → 小栗 → 波多野・遠藤 |
| 5 | 全動球が止まったら勝敗を確認。続ける場合は敵を追加し次の発射へ | 栗本・波多野 |
| 6 | 手数・HPなどを画面に表示 | 黒野・波多野 |

| 4 |は1フレームを小さな時間（最初は4等分）にして繰り返す。入力は1フレームに1回だけ。
     ゲーム終了後は更新しないが描画は続ける。最後の手を使った瞬間ではなく、最後の球が止まってから勝敗を決める。

仮ルール：プレイヤー→敵・ボス、移動中の敵→ボスだけにダメージを発生させる。
　　　　　敵同士は弾き合うがダメージなし。反射回数は発射前に全動球を0にし、
　　　　　壁・固定物への実際の反射だけ+1。球同士も数えるかは未決定。
　　　　　ボス撃破と残り手数0が同時なら仮にクリア優先。
　　　　　雑魚全滅条件、敵追加数、ダメージの倍率、停止対象などは企画と確定する。

6. 全員が守ること

- 他の人のcppを変えるのではなく、hにある関数を使う。関数名・引数の型・戻り値を変えたい場合はリードに相談する。
- SceneGame.h/.cpp, GameObject.h/.cpp, Component.h, ComponentRegistry.cpp,
  GameTypes.h, SceneSerializer.cpp, DebugEditor.cpp, DirectX関連、共通Stage01.json、
  プロジェクト設定（vcxproj/filters）はリード管理。
  自分のcppをVSに追加するための変更は可。共通設定の競合はリードが解決する。
- 自分のテスト用ステージは別の名前で保存。DebugとReleaseをビルドし、テスト結果とともにPRを出す。

7. Componentを作ったら最後に行うこと

すべてのComponentに共通。既存のMoveComponent.h/.cpp、AutoRotateComponent.h/.cpp、
ComponentRegistry.cppのMove、AutoRotate登録を参考にする。

1. コンストラクタで 「: Component(pOwner)」 と書き、どの物体に付くかを基底クラスへ渡す。
2. GetTypeId() は保存用の名前。hに書かれた文字列を変えない。GetTypeName() はInspectorの表示名。
3. Clone(GameObject* pNewOwner) は新しく作った物体に付けるComponentを返す。
   設定値と有効/無効は引き継ぐが、ゲーム中の状態は初期値に戻す（速度0、ドラッグなし、HP最大、反射回数0）。
4. Inspector用の関数は #ifdef _DEBUG で囲む。ReleaseにはImGuiがない。
5. リードへ、作成方法（create）、JSONへの保存項目（save）、読み込み時のセット方法（load）を提出する。
   登録コードは別のテキストとして渡し、Registryへの追加はリードが行う。設定値だけ保存し、ゲーム中の変化は保存しない。

8. よく使う既存の関数

| 関数 | 何ができる？ |
＝＝＝＝＝＝＝＝＝＝
| `GetOwner()` / `m_pOwner` | 自分が付いているGameObjectを取得 |
|
| `GetTransform()` | 位置・回転・大きさを取得。`position[0]` がX、`[1]` がY、`[2]` がZ |
|
| `GetComponent<T>()` | 同じ物体に付いているT型の機能を探す。なければnullptr。const版は読み取り専用 |
|
| `HasComponent<T>()` | その種類が付いているか確認 |
|
| `AddComponent(unique_ptr<Component>)` | Componentを追加。成功したらtrue |
|
| `GetComponents()` | Component一覧を取得 |
|
| `IsEnabled()` / `SetEnabled(bool)` | Componentを有効・無効にする |
|
| `GetColor()` / `SetColor(XMFLOAT4)` | 色の取得・変更 |
|
| `GameObject::Update(float)` | 有効なComponentを順に更新（派生クラスで上書きしない） |
|
| `IsKeyTrigger/Press/Release(BYTE)` | 押した瞬間・押している間・離した瞬間の判定 |
|
| `Camera::GetViewMatrix(false)` / `GetProjectionMatrix(false)` | 座標変換用のカメラ行列（転置前） |
|
| `GetRenderWidth()/GetRenderHeight()` | 描画先の幅・高さ |

SceneRayPickerは開発用（_DEBUG）なので、Play操作には流用しない。Play用の座標変換はリード担当。

9. リードが追加する予定の共通機能

`GameObject::IsActive()` と `SetActive(bool)` は追加予定の関数。
現在のエンジンで未実装なら、リードの更新を待つ。
falseにした物体は描画・更新・衝突・HUDや生存数の集計から外す。Play開始時はtrueに戻す。JSONには保存しない。

Systemは普通のクラス。GameObjectに付けず、SceneGameにメンバ変数として置いて呼ぶ。
System専用の基底クラスやRegistryは作らない。

統合順：HP・HUD・移動/手数・衝突を各自でテスト → 発射から停止まで
　　　　 → 壁反射と連鎖 → HPと勝敗 → HUDと敵追加。
　　　　 最優先のSから。軌道表示(C)やArnold対応は後回しでよい。

補足：用語が分からなかったら

| 用語 | 意味 |
＝＝＝＝＝＝＝＝＝＝
| Component | 1つの物体に付ける機能や情報（HPや速度など） |
| System | 複数の物体やゲーム全体をまとめて処理する普通のクラス |
| API / 公開関数 | ほかのクラスから使ってよい関数の約束 |
| Inspector | エディタで選んだ物体の設定を表示・変更する欄 |
| Clone | コピーを作る関数。F1でPlayを開始するときにも使われる |
| Registry | Componentの種類と、作成・保存・読み込み方をまとめた一覧 |
| JSON | ステージの設定をファイルに保存する形式 |
| フレーム | ゲームの更新1回分。dtはそこで進める秒数 |
| サブステップ | 1回の時間を細かく分けて移動・衝突を繰り返す方法 |
| nullptr | 指している物体が存在しない状態 |
| NaN / Inf | 正常な数値ではない値。0除算などで発生する可能性がある |
| ブランチ / PR | 自分専用の作業場所 / 変更をmasterへ取り込んでもらう申請 |
